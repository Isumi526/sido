### 1.2 「全体見積」シートの列構成（実物）

**実データ例**
```

合計: 請負 ¥2,330,950 / 原価 ¥1,856,300 / 差引 ¥474,650 / 利率 20%
```

### 1.3 判明した計算ロジック（数値から逆算・全行一致を確認）

- 金額 = 数量 × 単価 ✔
- **見積単価 = 原価 ÷ (1 − 粗利率)** ✔（例: 2,700 ÷ 0.80 = 3,375）
  - **原価 × (1 + 率) ではありません**。粗利率ベースの割戻しです。
- **標準は20%**。ただし**I列（実際の提示単価）は20%列を人手で切りの良い数字に切り上げ**（¥3,375→**¥3,400**、¥4,125→**¥4,200**）
- 法定福利費: `請負金額 × 23% × 15%`（セル内に式の説明テキストとして記載）
- 表紙: 見積金額 → 消費税10% → 税込、法定福利費は別掲

### この回答から導かれる設計原則

1. **単価は「貯める作業」をさせない**（#15）
   → 業者から見積を受領して登録する、その1アクションで `項目 × 業者 × 単価 × 提示日 × 現場` が自動的に履歴に入る。
   Excelの `軽鉄価格 基本` シートが1項目しか埋まらなかったのは、**明細入力とは別に台帳へ手入力する設計だったから**（推測）。同じ轍を踏まない。

2. **マスタを先に整備させない**（#17）
   → 工種名・項目名は**自由記述**。入力されたものを蓄積し、次回から**予測変換・候補表示**で揃えていく。
   「まず工種マスタを作ってください」と要求する設計にしない（＝初期投入コストで頓挫する）。

3. **粗利率は階層で持つ**（#12）
   → アカウント既定 → 見積ごと上書き。表示は原価と併記し、**4パターンのプレビューは残す**（Excelの見比べ体験）。

## 1.9 ★健全な現物「0603版」の解析（数式が生きている本物） ★改訂3

`#13` で共有いただいたExcelを解析しました。**数式13,593件が生存・`#REF!`は0件**。
（先に解析した0213版は壊れたコピーで、こちらが本物です。）

### 1.9.1 計算ロジック（数式そのもの・確定）

```
【入力するのは原価側だけ】
  N列 数量（手入力）              O列 単位（手入力）
  P列 単価原価 = XLOOKUP(B列の項目名, テーブル5[項目], テーブル5[単価])   ← 単価マスタから自動
  Q列 金額原価 = N × P

【客先側は原価側から自動で生える】
  G列 数量 = N          H列 単位 = O
  I列 単価 = Y          ← 既定は「粗利20%の見積単価」
  J列 金額 = G × I

【粗利4パターン】R,T,V,X = P（原価のコピー）
  S = R / 0.95   （5%）
  U = T / 0.90   （10%）
  W = V / 0.85   （15%）
  Y = X / 0.80   （20%）  ← I列の既定値

【総括（項目シート）】
  各工種の J27 / Q27 をシート参照で集約
  小計       = SUM(J3:J23)
  法定福利費 = 小計 × 0.23 × 0.15
  端数調整   = 手入力行
  合計       = 小計 + 法定福利費 + 端数調整
  利率       = (請負 − 原価) ÷ 請負
```

### 1.9.2 ★これが「操作感」の正体（最重要）

| 事実 | 意味 |
| --- | --- |
| **`I列 = Y列` が数式で入っている**が、一部の行は `3400` `4200` と**手打ちで上書き**されている | **既定は自動、必要な時だけ手で殴れる**。Webで「自動計算だから編集不可」にすると即座に使われなくなる |
| **`P列 = XLOOKUP(項目名, テーブル5)`** | **項目名を打つと単価が自動で入る**。これが入力の主動線。既存Webビルダーの「材料を選ぶ」UIとは操作が別物 |
| `G=N` `H=O` `I=Y` と**客先側が全部数式** | 入力するのは**原価側だけ**。客先側は結果。Webも「原価を入れると客先が生える」向きにする |
| 粗利率が `/0.95` `/0.9` と**数式にハードコード** | **率を変えるには数式を書き換えるしかない**＝#12の「アカウント既定＋案件ごとに変更」は**Excelでは実現できていない**。Web化の明確な純増価値 |
| `J1 = NOW()` | 日付は自動 |
| K列に `概算` 等の自由記述 | 摘要欄が要る |

### 1.9.3 ★E1「全体見積→工種別の手コピペ撲滅」は**まだ手作業**

全18工種シートを走査した結果、**他シートを参照する数式は1件もありませんでした**（`項目`シートだけが工種シートを参照）。

```
全体見積 ──(手コピペ)──▶ 工種別18シート ──(数式で自動集約)──▶ 項目 ──▶ 表紙
          ↑ ここだけ人力                    ↑ ここは自動化済み
```

つまり **「全体見積に打った明細を、工種ごとに切り分けて18枚へ手で貼る」作業が実在**します。
既存Webの `estimate-builder` は「工種別内訳（自動）」を持っているので、**ここは既に解決済みの価値**です。ユーザーがそれを体感できていない可能性があります（❓確認19）。

### 1.9.4 単価マスタ「テーブル5」＝ `軽鉄価格 基本` シート

- XLOOKUPの参照先。**項目名（完全一致）で単価を1つ引く**構造
- **業者ごとの単価は引けない**（引けるのは自社の採用単価1つだけ）
- 相見積の3業者枠は**マスタの右側に置かれているだけで、数式で繋がっていない**（数式1件のみ）
  → **#15「手入力が面倒」の正体**: 業者見積を見て、人が「採用単価」を決めて左側に手打ちしている

### 1.10.5 積算システム化の結論

| 案 | 評価 |
| --- | --- |
| **(a) 図面からAIで全自動に数量算出** | ❌ **非推奨**。平面図に内部寸法が無く、壁高さが多義、仕上げ区間と寸法が非連動、かつ「中止」項目を機械的に拾う。**静かに間違った数量を出す**のが最悪の失敗モード |
| **(b) 凡例の面積表だけ自動取込** | ⭕ **限定的に強く有効**。床・置床・天井・建具・器具台数は確定値で書かれており誤差ほぼゼロで取れる。**ただし壁は対象外**（金額の主戦場が穴） |
| **(c) 人が読んだ寸法を入れると面積計算・数量展開を補助（計算機＋履歴）** | ⭐ **推奨の中核**。真の痛点は「測ること」ではなく**「12.86×2.8=35.8 の過程が残らないこと」**。過程が消えるため①仕様変更で再計算が総やり直し ②根拠を説明できない ③次案件に蓄積しない |
| (d) やらない | ❌ 展開図22面・造作13点・仕上げ18コードを毎案件手拾いしており、変更のたび全量やり直し。記録化・再利用の価値は大きい |

**推奨: (c)を土台に、(b)を限定的に自動化する**

実装順序:
1. **凡例の確定数量を自動取込**（(b)）— 床/置床/天井/建具/器具台数。**天井合計 vs 通り芯面積の自動検算**つき
2. **展開図ベースの壁面積計算機＋履歴**（(c)）— 幅チェーンの加算、高さは`CH/欄間/スラブまで`から**選択式**（曖昧さを人の1クリックに閉じ込める）、開口控除、工種展開（PB両面二層=×4等）、ロス率
3. **Vision は「転記支援」に限定** — 寸法を候補提示し、人が採否。**自動確定しない**
4. **(a)の全自動は当面やらない**。やるなら前提は**元CADデータ(DWG)を受領する商流に変えること**で、これは技術ではなく取引条件の問題

## 1.11 ★確認19の回答と、そこから導かれた最重要の結論

> **❓確認19**: 既存Webビルダーには「工種別内訳（自動）」が既にあるが、体感されているか
> **✅回答: 「自動化は必要！」**

つまり **機能は既に存在するのに、ユーザーに届いていません**。

```
現状:  入力UIが合わない → ビルダーを使わない → 既にある自動分割に到達しない → Excelで手コピペを続ける
```

→ **入力の操作感を直すことが、新機能を足すことより優先**です。
「工種別自動分割」は**作る対象ではなく、到達可能にする対象**。

### ❓確認12: 粗利の計算式 ★最重要

確認7で「**(a) 下請単価に一律の掛率**」と回答いただきましたが、Excelの実データは

> **見積単価 = 原価 ÷ (1 − 粗利率)**（標準20% → 原価の1.25倍）

でした。「掛率」という言葉から想像される `原価 × 1.2` とは**5%ずれます**（原価2,700なら 3,375 vs 3,240）。

- **A. Excelどおり `原価 ÷ (1 − 率)` で実装する**（現行踏襲）
- **B. `原価 × (1 + 率)` が正しく、Excelの方がたまたまそうなっていただけ**

どちらでしょうか。**ここを間違えると全案件の金額がずれます。**
