# 図面の材料抽出をジョブとして扱う（R53）

出所: 2026-07-30 ユーザー通しレビュー（第5回）／Notion 【見積R53】・【見積R56】

## 何が問題だったか

実施図面から材料（メーカー品番・数量）を読み取る処理は、1ページずつ Edge Function
（`drawing-material-extract`）に投げる。**54ページの実図面で数分かかる**。

これを見積ビルダーの中の `ref` に持ち、モーダルで表示していたため、

- モーダルを閉じられない（閉じると状態が消える）
- 別の画面（マスタ・担当者）へ移った瞬間に解析が死ぬ
- 何ページ目まで進んだのか分からない

となり、実際に「解析が終わるまで他の作業ができない」状態になっていた。

## 採った形：画面の外で走らせ、1ページごとにDBへ保存する

実行を `apps/admin/src/lib/extractJobs.ts`（モジュールスコープ）に置いた。
コンポーネントが unmount されても走り続けるので、**SPA内の画面遷移では解析が止まらない**。

進捗と結果は `estimate_drawing_extract_jobs` に**1ページ終わるごとに**書く。

| 列 | 意味 |
|---|---|
| `total_pages` / `done_pages` | ここまで解析済み。**再開は done_pages の次のページから** |
| `rows` (jsonb) | 読み取り結果。ページ単位で積む（明細に入れるかは人が選ぶ） |
| `status` | `running` / `paused` / `done` / `error` |
| `acked_at` | 人が結果を見た時刻。ナビのバッジはこれが空の `done` を数える |

`attachment_id` に一意index を張って **1図面1ジョブ**にしている。やり直しは同じ行を使う。

### 状態の読み替え（大事なところ）

DBに `running` で残っているジョブは、**タブを閉じて中断されたもの**である
（走っている間だけ手元のメモリに実行中フラグがある）。
そのため `loadJobsForProject()` は、手元で走っていない `running` を **`paused` として見せる**。
これをしないと、誰も動かしていないジョブを「解析中」と表示し続けることになる。

### 再開とやり直しの違い

- `paused`（タブを閉じた）→ **続きから**（`done_pages` の次のページ）
- `error`（通信断など）→ **続きから**。54ページの途中で落ちて全部やり直しは実用にならない
- `done` → **0ページ目から**（＝人が意図した「やり直し」）

### 二重起動

実行中フラグの登録は**最初の `await` より前**に置く。
`await` の後だと、ボタンを素早く2回押した時に両方が通り、同じページを2回解析して
結果が二重になる（実装時に踏んだ）。

## 完了の知らせ方

解析が終わった時点で `refreshExtractBadge()` を呼び、ナビの「見積もり」に件数バッジを出す
（`App.vue` が `extractDoneCount` を描画）。
結果を開いた時に `acked_at` を入れてバッジから落とす。

画面遷移を待たずに出るのが肝で、**別の画面で作業している最中に終わっても気づける**。
併せて、見積ビルダーのタブ列に「材料抽出中 n/Nページ」を常時出している
（案件情報タブの図面一覧にしか進捗が無いと、明細を打っている間は分からない）。

## 採らなかった形：サーバー側で完走させる（R56・保留）

「ブラウザを閉じても完走する」にはサーバー側で回す必要があるが、

- Edge Function には実行時間の上限があり、**54ページを1回の呼び出しで処理できない**
  （実際に wall clock の警告／打ち切りが出る）
- したがって「ジョブテーブル＋定期実行ワーカーが数ページずつ処理する」形が必要になり、
  再試行・重複実行防止・失敗通知まで設計が要る

2026-07-30 のユーザー選択は **「タブを閉じたら再開」**（＝本ドキュメントの形）。
将来これで運用が回らないと分かった時点で R56 を起こす。
**その時も「1回の呼び出しで処理するページ数に上限がある」制約は残る**ので、
ページ単位で進捗を持つ本設計はそのまま土台になる。
