# マスタ編集の共通ルール

出所: 2026-07-29 ユーザー通しレビュー（第3回）／Notion 【見積R27】

## なぜルールにするか

マスタ（工種・自社情報・商社単価表など）の編集がそれぞれ別の画面に散っていて、
「入力の途中でマスタを直したい」たびに**書きかけの画面から離れる**必要があった。
見積のように1画面で長時間作業するものでは、これが実際に手を止める原因になる。

## ルール

### 1. ページ遷移せず、その場のモーダルで編集する

マスタを使う画面から離れずに直せること。設定画面へのリンクだけを置くのは不可。

- ✅ 見積ビルダー → 工種の編集ボタン → モーダル
- ✅ 見積書プレビュー → 自社情報の編集ボタン → モーダル
- ❌ 「設定画面で登録してください」とリンクだけ出す

ただし**印影の登録のような重い設定**は専用ページに残してよい。その場合も
「よく直す項目だけモーダル、細かい設定は専用ページへの導線」の形にする。

### 2. 追加した瞬間に反映する

モーダルを閉じるまで候補に出ない、再読み込みが要る、という作りにしない。
追加したその場で使えること（追加 → すぐ選ぶ、が同じ流れでできる）。

実装上は、DBへ書いた結果を**手元の一覧に直接足す**。
全件読み直しはコストが高く、入力のたびに走らせられない。

### 3. 編集ボタンは「そのマスタを使う場所の近く」に置く

画面上部やメニューではなく、対象の入力欄の隣。探させない。

- ✅ 工種の入力欄の隣に鉛筆アイコン
- ✅ 自社情報は見積書プレビューの中（＝発行元が出る場所）

### 4. 候補から消しても、既に作ったデータは変えない

マスタから項目を消す＝**候補に出なくなるだけ**。過去のレコードの値は書き換えない。

過去の見積の名称を後から書き換えると、**既に出した帳票と食い違う**。
消す時の確認ダイアログにもその旨を明示する。

### 5. 消しても再び候補に出るケースは、その理由を伝える

候補が複数の出所から作られている場合（例: 名称・品番の候補は
「商社単価表 ＋ 過去に打った明細」から作られる）、片方だけ消しても再び出てくる。
黙って復活すると「消えない」と受け取られるので、確認ダイアログで理由を伝える。

## 適用状況

| 対象 | 画面 | 状態 |
|---|---|---|
| 工種 | 見積ビルダー（工種入力欄の隣） | ✅ R27 |
| 自社情報 | 見積書プレビュー内 | ✅ R26 |
| 名称・品番の候補 | 見積ビルダー（明細ツールバー） | ✅ R21 |
| 商社単価表 | マスタ画面 | 単価表の一本化は R28。モーダル化は未 |
| 元請け・その担当者 | 見積ビルダー（元請け選択欄の隣） | ✅ R55（2026-07-30 第5回レビュー） |
| 現場・業者などの他マスタ | 各画面 | 未（本ルールを順次適用する） |

### 元請け（R55）で分かったこと

元請けだけは「マスタが無いと先に進めない」種類のマスタだった。
見積書の送信先が決まらないと帳票を出せないため、未登録に気づいた時点で必ず
`/contractors` へ移動していた。**移動して戻ると書きかけの見積が消える**という
実害が出ていたので、ここは特にルール1（ページ遷移しない）が効く。

併せて、追加した元請けは**その場でその案件の元請けに紐付ける**ようにした。
「追加はできたが選び直しが要る」形はルール2の趣旨（追加 → すぐ使える）を満たさない。

## 未適用のものについて

このルールは見積に限らないが、全画面への一括適用はしていない。
画面ごとに「よく直す項目」が違うため、**その画面で実際に手が止まる項目から**適用する。
新しくマスタ参照のUIを作る時は、最初からこのルールに従うこと。
