# GENLINKS が保管する個人情報の一覧

作成: 2026-08-31（本番DBの実スキーマと実データを見て作成。推測は含めない）
用途: サービス利用契約書・別紙（安全管理措置／取り扱う情報の範囲）に添付する正本。

> **この一覧に無いものは取り扱わない。** 列を足す時はこの文書も直すこと。
> 「契約書には書いていないが実は持っている」を作らないための文書なので、
> 実装を変えたらここを更新するまでが1セット。

---

## 1. マイナンバー（個人番号）は取り扱わない

**本番DBに該当する列は1つも存在せず、コードにも一切現れない**（2026-08-31 実測）。

- `information_schema.columns` を `my_number` / `mynumber` / `個人番号` で検索 → **0件**
- `apps/` `supabase/functions/` `shared/` を同語で検索 → **0件**

現状の機能（日報・経費・勤怠・見積）に個人番号が要る処理は無い。
**今後も保管しない方針**とし、必要になった場合は別途契約と安全管理措置の見直しを行う。

### 家族構成は取り扱わない
`family` / `dependent` に相当する列は**存在しない**（2026-08-31 実測）。
契約書で「家族構成」に言及する場合は、**保管しない側**に記載すること。

### 履歴書などの添付
`worker_attachments`（`kind` / `name` / `path`）でファイルを保管できる作りはあるが、
**本番の登録は0件**（2026-08-31 実測）。保管する場合は非公開バケットに置き、
表示のたびに短時間だけ有効なURLを発行する（`worker-attachment-url`）。

## 3. 業務データに含まれる個人に関する情報

| 種別 | どこに | 中身 |
|---|---|---|
| 日報 | `daily_reports` | 誰がいつどの現場で何時間働いたか、経費、備考 |
| 経費の領収書 | `expense-receipts-v2`（非公開） | 支払先・金額・インボイス番号。画像に氏名が写ることがある |
| 個人経費 | `personal_expenses` | 立替の内容・金額・領収書 |
| 出退勤 | `attendance_logs` | 打刻の時刻。**★位置情報（緯度経度）を実際に記録している**（`location_lat` / `location_lng`。本番39件中33件に値あり・2026-08-31実測）。同意した確認ルールの文面(`agreed_rule_texts`)・同意した書類名(`agreed_document_names`)も保持 |
| 有給 | `paid_leave_grants` / 日報の `leave_type` | 付与・消化 |
| チャット | `site_chat_messages` | 本文と添付 |
| LINE連携 | `users.line_user_id` | LINEの利用者ID（本人特定に使う。氏名や電話は取得しない） |

## 4. 取り扱わないもの（明示）

- **マイナンバー（個人番号）**
- **家族構成・扶養情報**
- 銀行口座（※`subcontractors` に協力業者の振込先はあるが、これは**法人の口座**であって作業員個人のものではない）
- 健康診断の結果そのもの（受診日のみ保持。結果は保管しない）

### ★位置情報について（契約書に書く時の注意）
出退勤の打刻時に**緯度経度を記録している**。「取り扱わない」側に書いてはいけない。
本番では39件中33件に値が入っている（2026-08-31実測）。
不要なら記録をやめる判断もあり得るが、**現状は取得・保管しているので、そのとおりに書く**。

## 5. 保護の仕組み（2026-08-31 時点）

- 会社ごとにデータを分離（`account_id` ＋ RLS）。
- ファイルは**非公開の保管庫**に置き、見るたびに短時間（5分）だけ有効なURLを発行する。
  - ★2026-08-30 に旧保管庫（`expense-receipts`）が公開のままだったのを塞いだ。
    それまでは鍵無しでも取得できる状態が続いていた。
- 賃金など★の項目は、権限のある管理者だけが見られる（列単位の権限で制御）。
- 匿名の公開キーからは、作業員・日報・打刻などの表を直接読めない。
