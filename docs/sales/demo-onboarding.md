## 2. ローカル通し検証で分かったこと（2026-09-20・空テナント `kakunin-demo`）
- ✅ 発行 → 初回ログイン → 各設定画面の表示は空データで壊れない（自社情報／作業員／現場／作業区分／設定／道具／日報一覧）。作業区分は既定5件が入る。
- ✅ 作業員の追加は保存される（DB に行が入る）。
- ⚠ 発見①: **作業員の追加後、モーダルが閉じず一覧が「有効 0」のまま**（保存自体は成功）。再読み込みで出る。原因未特定（保存後の後処理で止まっている可能性）。→ 別チケット候補。
- ⚠ 発見②: ログイン直後から **別テナント（ビルド時 env の slug）の account_id でバッジ用ポーリング（承認待ち件数・残業申請・日報等）が anon 権限で走り 401 を大量に出す**。画面は動くが、コンソールが赤くなる＝デモで「エラー？」と聞かれる。新規テナントでは env の slug が自社と違うため必ず起きる。→ 別チケット候補（`useAccount`/バッジのポーリングをセッションの account に統一）。
- ⚠ 発見③: ダッシュボードの「お知らせ・更新履歴」が **新規テナントでも過去のリリースノート（未確認 18件）** を出す。空テナントには「次に何をするか」の案内が無い（→ 提案 §4）。
- ⚠ 発見④: 作業員のログイン（email/pw）発行は GoTrue の admin API 経由。**ローカルでは 403（既知）**のため、手順 4 の「ログイン用 email＋パスワード」→ 手順 8 の作業員ログイン → 9 の日報送信は **ローカルでは通せていない**（staging／本番で確認する＝AC5 と合わせて人が実施）。
- CLI のみで画面が無い操作: アカウント発行（0-1）、月額 `monthly_fee_yen` の設定（SQL）。

## 4. 提案（実装は別チケット・ここでは作らない）
- ダッシュボードに **「はじめの設定」チェックリスト**（拠点／作業員（ログインつき）／現場／通知）— 未設定の項目だけ出し、各画面へのリンク。全部済んだら消える。
- 新規テナントの「お知らせ・更新履歴」は **契約開始日より前のリリースノートを既読扱い** にする。
- 発見①②の修正。
